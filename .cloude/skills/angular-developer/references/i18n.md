# Internationalization with @angular/localize

## Setup

```bash
ng add @angular/localize
```

## Marking Text for Translation

In templates, use the `i18n` attribute (with optional meaning, description, and ID):

```html
<h1 i18n="site header|Main page title@@homeTitle">Welcome</h1>
<img [src]="logo" i18n-alt alt="Company logo" />
```

In TypeScript, use the `$localize` tagged template:

```ts
protected readonly greeting = $localize`:@@greeting:Hello, ${this.name()}:name:!`;
```

## Extraction and Translation Files

```bash
ng extract-i18n --output-path src/locale
```

This produces `messages.xlf` (XLIFF). Create one translated copy per locale (e.g. `messages.es.xlf`) and register them in `angular.json`:

```json
"i18n": {
  "sourceLocale": "en-US",
  "locales": {
    "es": "src/locale/messages.es.xlf"
  }
}
```

## Building per Locale

```bash
ng build --localize
```

Produces one bundle per locale (`dist/<app>/browser/es/`, etc.). Serve each under its own path or domain. There is no runtime language switching with `@angular/localize` — switching locale means loading a different build.

## Guidelines

- Always add `@@customId` to avoid churn when source text changes.
- Use ICU expressions for plurals and selects: `{count, plural, =0 {no items} one {one item} other {{{count}} items}}`.
- Pipes (`DatePipe`, `CurrencyPipe`, `DecimalPipe`) format according to the active `LOCALE_ID` automatically in localized builds.
- If runtime switching is a hard requirement, document the decision (ADR) before adopting a third-party runtime i18n library.
